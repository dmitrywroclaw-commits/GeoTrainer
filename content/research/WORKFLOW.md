# Быстрый выпуск проверенных карточек

Этот регламент дополняет `GeoTrainer Documents/06_CONTENT_PRODUCTION_PLAN.md` и `content/research/README.md`. Критерии отбора, источников, прав и полноты остаются в плане. Цель регламента — сократить повторный ввод данных и выпускать готовые записи пакетами, сохраняя проверку каждой карточки.

## Единица работы и очередь

- Аудит стран: пакет из 10–15 следующих стран базового реестра. Для каждой страны проверить национальный и государственный флаги, выбрать один с более подробным рисунком (при равенстве национальный) и проверить действующий национальный/государственный символ. Записать также `excluded` и `deferred` с причиной.
- Аудит природы: небольшой последовательный участок `nature-source-catalog.csv`. Каждую исходную территорию разобрать на конкретные именованные физические объекты; ноль объектов тоже является решением с причиной.
- Публикация: 5–10 **готовых** карточек из реестров. Пакет может объединять уже проверенные страны и природные объекты. Не ждать, пока все объекты одного исследовательского пакета получат разрешённое медиа.
- При препятствии занести ID, причину и следующий проверяемый шаг в `OPEN_QUESTIONS.md`, оставить запись `deferred` или неопубликованной `eligible` и перейти к следующей. Вернуться к очереди на завершающем этапе согласно плану № 6.

Перед новым пакетом посмотреть `git status`, последние изменения и незавершённые черновики. Не перезаписывать чужую или начатую работу. Выбрать конкретные ID пакета и зафиксировать их в его отчёте.

## Шаг 1. Проверить факты один раз

1. Для страны найти первичный акт, государственный образец или другое авторитетное подтверждение **действующего статуса** и вида выбранного национального или государственного флага. Для природного объекта подтвердить имя, местоположение, тип и значимость по авторитетному источнику. Не выводить факт из имени файла или изображения.
2. Записать источник в исследовательский пакет и `sources.csv`: ID, издателя, точный URL, дату доступа и утверждения, которые он поддерживает. По возможности указывать страницу или раздел длинного документа. Повторно использовать существующий ID источника, если он уже покрывает утверждение.
3. Отделить наблюдаемые элементы от объяснения их смысла. Для смысла символа использовать `official`, `well_sourced`, `interpretation` или `unknown`; неизвестное значение не дополнять догадкой. Для географических рекордов сохранять величину, метод измерения и оговорку.
4. Подготовить исследовательский JSON в `content/research/batches/` по существующему образцу. Проверить ID, ссылки, статусы и отрицательные решения до применения пакета.

Один источник может подтверждать несколько карточек. В реестре он получает один стабильный ID; будущая карточка ссылается на этот ID. Публикационный формат пока требует повторить сведения об источнике в JSON пакета — копировать их из проверенной записи, не искать и не переписывать заново.

## Шаг 2. Рано отсеять проблемы с медиа

Для каждой `eligible` записи до написания полного текста карточки взять готовое изображение из интернета (предпочтительно SVG), в том числе для гербов и эмблем, и проверить один конкретный файл:

- страница файла и прямой URL;
- автор и правообладатель, если указаны;
- лицензия или иной правовой режим, ссылка на условия и требуемая атрибуция;
- соответствие изображения действующему официальному образцу либо фактическому природному объекту;
- локальная копия и визуальная проверка её отображения.

Официальный сайт подтверждает факт, но сам по себе не разрешает перепубликацию изображения. Если права или точность образца не установлены, не публиковать карточку: оставить строку в очереди медиа и взять следующую готовую запись. Проверить лицензию на **дизайн** государственного символа отдельно от лицензии на исполнение конкретного SVG, если это существенно.

Публикационные скрипты сохраняют нетронутые реестры без перезаписи. Перед оценкой объёма работы смотреть на конкретные новые карточки и файлы медиа: общий счётчик строк в Git включает накопленные изменения больших JSON/CSV за несколько пакетов.

## Шаг 3. Подготовить публикационный пакет

1. Применить проверенный исследовательский пакет существующей командой `node scripts/research/apply-country-batch.mjs <путь>` или `node scripts/research/apply-nature-batch.mjs <путь>`. Эти скрипты рассчитаны на новый ID и не заменяют существующее решение: повторную проверку существующей записи оформлять как осознанное обновление, а не запускать тот же пакет снова.
2. Составить публикационный JSON по действующим примерам `publish-*.json`. Перенести ID страны, источников, типа и медиа из реестров. Вручную отредактировать короткие русские `summaryRu`, `explanationRu`, ключевые факты и теги похожести. Объяснение должно помогать узнать объект после ответа на вопрос.
3. Перед применением проверить каждую карточку по исходным страницам: источник каждого значимого утверждения; точный тип символа; `meaningStatus`; права и атрибуцию медиа; отсутствие неподтверждённого рекорда; полезность объяснения; отсутствие подсказки с ответом на экране вопроса.
4. Применить пакет командой `node scripts/research/publish-content-batch.mjs <путь>`. Скрипт переносит записи в `content/library.json`, `content/media.json` и реестры. Он не заменяет редакционную проверку фактов и прав.

До запуска любого скрипта применения проверить `git diff` и сохранить рабочий пакет. После запуска снова проверить diff: ожидаемые ID, число карточек, изменения CSV/JSON и только нужные медиа. Не включать временные HTML, скриншоты и рабочие загрузки в коммит.

## Шаг 4. Проверить и выпустить

После каждого публикационного пакета выполнить:

```sh
npm run research:validate
npm run typecheck
npm test
npm run build
```

Для изменения пользовательского поведения или расширения набора вопросов дополнительно запустить соответствующий Playwright сценарий: `npm run test:e2e`. Просмотреть несколько новых карточек на мобильной и широкой ширине, проверить изображения, источники, атрибуцию и объяснение после ответа. Достаточно одного полного цикла проверок на пакет; при исправлении сбоя повторить затронутую проверку и итоговую сборку.

Коммитировать согласованный исследовательский или публикационный пакет с кратким названием. После выпуска обновить `PROGRESS.md` и сообщить:

- сколько стран и исходных природных строк разобрано в пакете и всего;
- сколько карточек каждого типа опубликовано в пакете и всего;
- сколько `eligible` ждёт публикации, сколько `deferred` и сколько ждёт медиа;
- какие ID отложены и почему;
- какие проверки прошли;
- где заняло больше времени: источники, медиа, текст или перенос данных.

Считать эти показатели из реестров, а не из числа коммитов. Не объявлять `eligible` запись опубликованной, пока нет соответствующей карточки в `library.json`.

## Следующие автоматизации

Эти команды **ещё не реализованы**. Добавлять их небольшими отдельными изменениями после проверки на существующих пакетах:

1. Генератор черновика публикационного JSON по ID `eligible` записей: заполняет стабильные ID, страну, тип и уже проверенные источники; оставляет текст объяснения и решение о медиа редактору.
2. Проверка публикационного пакета до записи файлов: полнота медиа-метаданных, лицензия/атрибуция, наличие локального файла, ссылки на источники, дубликаты и соответствие строке реестра.
3. Автоматический отчёт покрытия из CSV и `library.json`, включая отдельные очереди «ждёт источник», «ждёт медиа», «ждёт редактуру» и «готово к публикации».

Проверить пользу на двух последовательных пакетах: время от выбора ID до опубликованной карточки, число ручных переносов одного источника и число возвратов из-за неполных прав/ссылок. Если ускорения нет, упростить инструмент, а не усложнять схему контента.

## Задание агенту для одного пакета

> Продолжи наполнение GeoTrainer по `AGENTS.md`, `GeoTrainer Documents/06_CONTENT_PRODUCTION_PLAN.md` и `content/research/WORKFLOW.md`. Сначала проверь `git status` и текущие незавершённые материалы. Возьми следующие 10–15 ещё не проверенных стран базового реестра **или** следующий небольшой участок природного каталога; не смешивай два исследовательских направления в одном задании. Проверь первичные источники и действующий статус каждого символа или факты каждого природного объекта. Запиши `eligible`, `excluded` и `deferred` с причинами. Рано проверь права на конкретные изображения. Из готовых записей собери публикационный пакет на 5–10 карточек, если столько готово; меньший пакет допустим, когда остальные требуют проверки. Не додумывай факты и значения символов. Вопросы занеси в `OPEN_QUESTIONS.md` и продолжай следующую запись. Примени существующие скрипты один раз для новых ID, проверь diff, выполни проверки из регламента и обнови `PROGRESS.md`. В конце сообщи покрытие реестра, опубликованные карточки, остаток очереди и причины задержек.
